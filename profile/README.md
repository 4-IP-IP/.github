## 一根专线4个IP怎么使用

一根专线提供4个公网IP时，最常见的方式是将这4个公网IP交由一台路由器、防火墙或者其他网络设备统一管理。

例如：

```text id="p0xq3m"
海外专线
    │
    ▼
路由器 / 防火墙
    │
    ├── 公网IP 1
    ├── 公网IP 2
    ├── 公网IP 3
    └── 公网IP 4
```

这4个IP可以根据业务需求采用不同方式使用。

例如：

```text id="q4h2jv"
方案一：4个IP全部由同一出口管理
方案二：不同设备分别使用不同公网IP
方案三：不同业务分别使用不同公网IP
方案四：服务器分别映射不同公网IP
方案五：通过SNAT指定不同设备的出口IP
```

因此，一根专线4个IP的关键并不是“怎么把4个IP同时插上去”，而是**如何根据线路交付方式建立正确的公网IP路由和映射关系**。

## 一根专线4个公网IP的基本网络结构

假设服务商提供4个公网IP，可以形成下面这样的网络架构：

```text id="0m2gzl"
                    海外专线
                        │
                        ▼
                 路由器 / 防火墙
                        │
          ┌─────────────┼─────────────┐
          │             │             │
          ▼             ▼             ▼
       业务设备A      业务设备B      业务设备C
          │             │             │
       公网IP 1       公网IP 2       公网IP 3

                    业务设备D
                        │
                     公网IP 4
```

实际情况下，并不一定是一台设备对应一个公网IP。

例如：

```text id="2d7b8e"
公网IP 1 → 多台内网电脑共享
公网IP 2 → 服务器A
公网IP 3 → 服务器B
公网IP 4 → 其他业务
```

具体分配方式取决于企业网络的用途以及路由设备支持的功能。

## 4个公网IP使用前需要准备什么

在正式配置之前，首先要向专线服务商确认完整的网络参数。

通常需要确认：

```text id="j4r4xk"
公网IP地址
子网掩码
默认网关
路由方式
DNS服务器
IP交付方式
是否支持多IP
```

例如下面只是一个示意：

```text id="90g5xg"
IP 1：203.0.113.10
IP 2：203.0.113.11
IP 3：203.0.113.12
IP 4：203.0.113.13

网关：203.0.113.1
掩码：由服务商提供
```

以上地址仅用于演示，实际配置必须使用服务商提供的真实参数。

还要重点确认这4个IP究竟是：

```text id="7g0b27"
同一子网直接交付
还是
通过静态路由交付
还是
通过上级设备进行映射
```

因为不同交付方式，对路由器的配置方法并不完全相同。

## 一根专线4个IP怎么配置到路由器

如果服务商允许4个公网IP在同一WAN接口使用，可以在支持多IP的企业级路由器或者防火墙中进行配置。

基本流程如下。

### 第一步：进入WAN设置

登录路由器管理后台，找到：

```text id="w0g7zt"
WAN设置
Internet设置
网络接口
公网IP
```

不同品牌设备的菜单名称可能不同。

### 第二步：配置主公网IP

首先按照服务商提供的信息配置主IP：

```text id="r6f2xl"
WAN IP
Subnet Mask
Default Gateway
DNS
```

保存后确认专线能够正常访问互联网。

### 第三步：添加其他公网IP

如果路由器支持IP Alias、多WAN IP或者附加公网IP，可以继续添加剩余3个地址。

示意结构：

```text id="h8r8wk"
WAN接口

主IP：203.0.113.10
附加IP：203.0.113.11
附加IP：203.0.113.12
附加IP：203.0.113.13
```

但需要特别注意：

**不能直接照着这个示例填写。**

实际是否需要单独设置子网、是否需要增加静态路由，应完全按照服务商提供的交付方案执行。

## 多个公网IP如何通过NAT使用

如果内网设备使用私有IP，例如：

```text id="qz9tmt"
192.168.1.10
192.168.1.11
192.168.1.12
192.168.1.13
```

就可以通过NAT将内网流量转换到公网。

最简单的情况是：

```text id="z7o2s5"
多个内网设备
      │
      ▼
   路由器
      │
      ▼
公网IP 1
```

这种情况下，4个公网IP并不会自动全部被利用。

如果希望真正使用多个公网IP，则需要结合SNAT、策略路由或者端口映射进行进一步配置。

### 端口映射

如果主要是让公网访问内网服务器，可以采用DNAT/端口转发：

```text id="h4b7ue"
公网IP 1:端口A
       ↓
内网服务器A

公网IP 2:端口B
       ↓
内网服务器B
```

这种方式非常适合多个公网服务器服务。

## SNAT怎么让不同设备使用不同公网IP

如果目标是让不同内网设备访问互联网时显示不同的公网IP，则可以使用SNAT规则。

例如：

```text id="s2i5yv"
192.168.1.10 → SNAT → 公网IP 1
192.168.1.11 → SNAT → 公网IP 2
192.168.1.12 → SNAT → 公网IP 3
192.168.1.13 → SNAT → 公网IP 4
```

这样4台设备对外访问时，可以分别使用4个不同的公网出口。

也可以按照网段划分：

```text id="66h9n7"
办公网段   → 公网IP 1
业务网段A  → 公网IP 2
业务网段B  → 公网IP 3
服务器网段 → 公网IP 4
```

这是多IP企业网络中比较常见的设计思路。

需要注意的是，具体SNAT配置命令会因路由器、防火墙品牌以及操作系统不同而变化，因此不能用一套命令适配所有设备。

## 策略路由如何分配4个公网IP

如果需要更加灵活地使用4个IP，可以结合策略路由。

策略路由可以根据不同条件匹配流量，例如：

```text id="03opgd"
源IP
目标IP
端口
协议
VLAN
设备
业务网段
```

然后为匹配到的流量设置不同的出口策略。

例如：

```text id="6e2g2r"
设备A → 公网IP 1
设备B → 公网IP 2
设备C → 公网IP 3
设备D → 公网IP 4
```

也可以进一步按照业务规则进行划分：

```text id="h2zjng"
业务系统A → 公网IP 1
业务系统B → 公网IP 2
海外办公 → 公网IP 3
服务器业务 → 公网IP 4
```

相比简单的端口转发，策略路由能够提供更加灵活的多IP流量控制。

## 4个公网IP怎么分配给4台电脑

假设有4台电脑：

```text id="2m5lqp"
电脑A：192.168.1.10
电脑B：192.168.1.11
电脑C：192.168.1.12
电脑D：192.168.1.13
```

想让它们分别使用4个海外公网IP，可以在路由器中建立对应的SNAT规则：

```text id="e5g97z"
电脑A → 公网IP 1
电脑B → 公网IP 2
电脑C → 公网IP 3
电脑D → 公网IP 4
```

同时需要保证：

```text id="2k7v6p"
电脑使用正确的默认网关
路由器能够正确识别源地址
SNAT规则优先级正确
4个公网IP已经由服务商正确路由
```

配置后，不应只查看电脑本地IP，还应该通过公网IP查询方式确认不同设备的实际出口是否已经按照预期变化。

## 4个公网IP怎么分配给服务器

如果有4台服务器，也可以根据网络需求进行对应配置。

例如：

```text id="uyr4if"
服务器A → 公网IP 1
服务器B → 公网IP 2
服务器C → 公网IP 3
服务器D → 公网IP 4
```

这种场景常见于企业部署多个业务服务。

另一种方式是使用NAT：

```text id="4xk9ps"
公网IP 1 → Web服务器
公网IP 2 → API服务器
公网IP 3 → 文件服务器
公网IP 4 → 远程管理服务器
```

此时需要同时配置：

```text id="5c46jq"
公网IP
端口转发
内网服务器地址
服务器监听端口
防火墙规则
```

不建议为了方便而开放大量不必要的公网端口。

## 一根专线4个IP能否同时使用

可以，但前提是：

**专线服务商已经将4个公网IP正确交付给用户，并且路由器或者防火墙支持相应的多IP配置。**

“同时使用”也有不同理解。

### 同时作为多个出口

可以：

```text id="8vdkri"
业务A → IP 1
业务B → IP 2
业务C → IP 3
业务D → IP 4
```

### 同时映射到多个服务器

也可以：

```text id="0ou8iz"
IP 1 → Server A
IP 2 → Server B
IP 3 → Server C
IP 4 → Server D
```

### 所有设备共享一个IP

当然也可以，只是不需要使用其他3个公网IP。

因此，4个IP是“资源数量”，如何使用则取决于企业网络架构。

## 4个公网IP和专线带宽有什么关系

4个公网IP不代表自动拥有4倍带宽。

例如：

```text id="6x7yqj"
4个IP + 100M专线
```

仍然可能只有100M总带宽。

公网IP主要解决的是：

**公网地址和网络出口标识问题。**

专线带宽解决的是：

**整个网络的数据传输能力问题。**

所以：

```text id="f3ef98"
1个IP + 100M
4个IP + 100M
4个IP + 300M
```

三种方案的公网IP和带宽配置不同。

如果4个IP背后的业务总流量不大，100M可能就够用。

如果4个公网IP分别对应高流量业务，则需要根据总并发流量增加带宽。

## 一根专线4个IP配置常见问题

### 为什么配置了4个IP，实际只能用1个？

常见原因包括：

```text id="z4yw9x"
服务商只路由了主IP
其他IP没有正确交付
路由器不支持多IP
缺少静态路由
SNAT规则没有配置
```

应先向服务商确认4个IP的具体交付方式。

### 4个IP是否必须全部配置到WAN口？

不一定。

有些网络需要将IP直接配置到WAN接口，有些则通过SNAT、路由或者公网IP映射使用。

具体方法取决于线路架构。

### 一个路由器可以管理4个公网IP吗？

可以，但需要看设备功能。

企业级路由器、防火墙通常比普通家用路由器更适合多公网IP配置。

### 4个IP可以给4台电脑分别使用吗？

通常可以通过SNAT或者策略路由实现，但前提是服务商已经正确提供4个公网IP，并且网络设备支持相应功能。

### 4个IP需要4条网线吗？

不需要。

如果4个IP由同一条专线交付，通常可以通过同一个WAN接口进行统一管理，具体物理连接方式取决于线路设备。

### 4个IP可以设置不同地区吗？

一般不能把“同一专线的4个IP”简单理解为4个不同国家的网络出口。IP归属地区和线路交付方式由服务商的IP资源决定，需要提前确认具体IP所在地区及网络属性。

## 多公网IP配置注意事项

### 确认IP交付方式

这是最重要的一步。

需要先确认服务商是采用：

```text id="p19c9x"
同网段交付
静态路由
上游设备映射
其他专用交付方式
```

### 不要自行猜测网关

公网IP、掩码和网关必须按照服务商提供的信息配置。

### 确认设备支持多IP

普通家庭路由器不一定支持复杂的多IP路由、SNAT和策略路由。

### 合理使用公网端口

公网服务器只开放必要端口，并配合防火墙和访问控制。

### 不要把IP数量和带宽混为一谈

4个IP只是4个公网地址资源，并不代表带宽自动增加。

### 配置后进行多时段测试

建议同时观察：

```text id="v2q8dt"
延迟
丢包
下载速度
上传速度
IP出口
高峰期稳定性
```

这样才能判断多IP专线是否真正达到预期效果。

## 总结

一根专线4个IP怎么使用，核心取决于服务商提供的IP交付方式以及路由器、防火墙支持的网络功能。

最常见的使用方式包括：

```text id="t0nq1u"
4个公网IP统一管理
        ↓
路由器 / 防火墙
        ↓
SNAT / NAT / 策略路由
        ↓
不同设备 / 不同服务器 / 不同业务
```

例如，可以设置：

```text id="3skjkm"
设备A → 公网IP 1
设备B → 公网IP 2
设备C → 公网IP 3
设备D → 公网IP 4
```

也可以将4个公网IP分别映射到不同服务器。

需要特别注意的是，一根专线提供4个IP，并不意味着必须使用4台设备，也不意味着带宽会自动增加。**IP数量解决的是公网地址资源问题，专线带宽解决的是网络流量承载问题。**

在实际部署过程中，建议按照：

**确认4个IP的交付方式 → 配置WAN → 添加公网IP → 配置NAT/SNAT或策略路由 → 测试公网出口 → 验证实际业务**

这一流程进行。

对于跨境电商、海外办公、独立站和服务器等业务，多IP专线能够提供更加灵活的公网网络出口，但最终配置方式仍应以服务商提供的线路参数和网络架构为准。
